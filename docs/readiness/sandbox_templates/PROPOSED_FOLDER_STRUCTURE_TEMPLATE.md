## The organising principle

Three sources of truth, kept apart on purpose, because most of the confusion in a long-lived working folder comes from mixing them:

1. **Repositories contain implementation truth.** What the software actually does is settled by the code and its tests, in Git — never by a document in a folder describing what it was meant to do.
2. **Folders contain research and knowledge evidence.** This Sandbox holds the thinking, the exploration, the evidence and the record. It does not hold implementation truth, and a design document here never overrides the code.
3. **Mike supplies operational truth and authority.** What is actually happening in the business, what has been decided, and what is doctrine — those come from Mike. No file and no tool can supply them, including this one.

The structure below follows from that. It separates material by *what kind of truth it can carry*, rather than by topic, which is why there is a `50_Doctrine_Candidates` and deliberately no `Doctrine`.

## Rules that come with the structure

- Nothing is deleted to create it. Superseded material moves to `70_Historical`.
- `40_Decisions` and any future `Doctrine` folder are populated by Mike, never by a classifier.
- `Dispatch\` is this tool's output folder and is excluded from every future survey's inventory, so the map never reads its own reports back in.
- Implementation truth does not live here at all. If a document in this Sandbox and the repository disagree about what the software does, the repository is right and the document is Historical.

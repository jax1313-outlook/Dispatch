# User Acceptance Testing (UAT) Checklist

Run through each section to validate CIN-Lite before production deployment.
Mark each item pass/fail. All items in Sections 1–4 must pass.

## Section 1: Installation and Setup

```bash
pip install .
```

- [ ] `pip install .` completes without errors
- [ ] `cin-lite --help` shows usage information
- [ ] `cin-lite --health` reports HEALTHY (exit code 0)
- [ ] `cin-lite --list-actions` shows 5 actions

## Section 2: Core Pipeline (sample data, no API keys)

Unset all integration keys first:

```bash
unset CIN_LITE_SAM_API_KEY ANTHROPIC_API_KEY CIN_LITE_SMTP_HOST
```

### 2a. Non-interactive batch mode

```bash
cin-lite --action reject
```

- [ ] Pipeline runs to completion without errors
- [ ] Console output shows contracts being processed
- [ ] Archive directories created under `Archive/`
- [ ] Each contract has files in `Archive/Raw/`, `Processed/`, `Intelligence/`, `Summaries/`, `Routing/`
- [ ] Contract IDs follow the format `CIN-YYYYMMDD-XXXXXXXX`
- [ ] Summaries use deterministic fallback (mention "flag(s)")
- [ ] Routing files contain `action`, `reason`, `priority`, `recipient`
- [ ] Emails written to `Archive/Outbox/*.eml` (offline mode)

### 2b. Interactive mode

```bash
cin-lite
```

- [ ] Each contract displayed with its analysis
- [ ] Prompt shows the 5 action choices
- [ ] Agent recommendation shown (marked `<- recommended`)
- [ ] Pressing Enter accepts the recommendation
- [ ] Typing an action name applies that action
- [ ] Archive updated after each decision

### 2c. Proposal trigger

```bash
cin-lite --action approve_proposal
```

- [ ] Proposal brief generated in `Archive/Proposals/<id>.json`
- [ ] Proposal outline generated in `Archive/Proposals/<id>.md`
- [ ] Brief contains milestones, requirements checklist, priority, team
- [ ] Outline contains standard GovCon sections (deterministic fallback)
- [ ] Kickoff email written to `Archive/Outbox/`

## Section 3: Rule Modules

Run with sample data and verify each rule produces output:

```bash
cin-lite --action flag_review
```

Check `Archive/Intelligence/` — each contract should have a JSON file containing
results from all 9 rule modules:

- [ ] `set_aside` — detects set-aside type or "None detected"
- [ ] `naics_sin` — extracts NAICS codes
- [ ] `pricing_anomaly` — flags pricing issues or reports clean
- [ ] `past_performance` — detects PP requirements
- [ ] `vendor_network` — identifies competition indicators
- [ ] `subcontractor_dominance` — checks subcontracting patterns
- [ ] `jv_mp_structure` — detects JV/MP arrangements
- [ ] `foreign_influence` — checks ITAR/EAR/FOCI/889
- [ ] `cyber_compliance` — checks CMMC/NIST/DFARS/FedRAMP

Each module output should have: `module`, `version`, `flags`, `risk_level`, `score`, `details`.

## Section 4: Operations

### 4a. Metrics

```bash
cin-lite --action reject
cin-lite --metrics
```

- [ ] Metrics file created at `logs/metrics/pipeline.jsonl`
- [ ] `--metrics` displays run count, contracts processed, action distribution
- [ ] Timing data is present and reasonable (<60s per contract for deterministic)
- [ ] Error count is 0

### 4b. Logging

- [ ] Log file created at `logs/cin_lite.log`
- [ ] Log entries include timestamps and structured context
- [ ] Console output is colored INFO level
- [ ] File output contains DEBUG detail

### 4c. Health checks

```bash
cin-lite --health
```

- [ ] Shows status for all 6 subsystems
- [ ] All show OK when integrations are unconfigured
- [ ] Exit code is 0

## Section 5: Integration Tests (optional — requires API keys)

### 5a. SAM.gov live acquisition

```bash
export CIN_LITE_SAM_API_KEY=your-key
cin-lite --action flag_review
```

- [ ] Real solicitations fetched from SAM.gov
- [ ] Contracts processed through all rule modules
- [ ] Health check shows SAM API key present

### 5b. Claude AI summarization

```bash
pip install ".[claude]"
export ANTHROPIC_API_KEY=sk-ant-...
cin-lite --action flag_review
```

- [ ] Summaries generated by Claude (not deterministic fallback)
- [ ] Routing recommendations use Claude's structured output
- [ ] Health check shows Claude API reachable

### 5c. SMTP email delivery

```bash
export CIN_LITE_SMTP_HOST=your-smtp-host
export CIN_LITE_SMTP_PORT=587
export CIN_LITE_SMTP_USER=your-user
export CIN_LITE_SMTP_PASSWORD=your-password
export CIN_LITE_EMAIL_FROM=cin-lite@yourdomain.com
export CIN_LITE_EMAIL_REVIEWER=lead@yourdomain.com
cin-lite --action flag_review
```

- [ ] Emails sent via SMTP (not written to Outbox)
- [ ] Reviewer receives decision email
- [ ] Health check shows SMTP connected
